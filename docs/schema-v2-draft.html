Each admin action below lists the tables it touches, in order. Not all operations are final — e.g. comment moderation has no approval column yet (flagged as an open question).

Add a category

INSERTCategorynew row (name, slug, parent_id)
INSERTAdminActionLogaction=create, entity_type=Category

Add a product

INSERTProductnew row (product_code, name, category_id, base_price, is_active=true)
INSERTProductSpecnew row (fabric, care_instructions, origin_country) — 1:1 with Product
INSERTAdminActionLogaction=create, entity_type=Product

Add a variant

INSERTVariantnew row (product_id, sku, band/cup or size_label, color, stock_qty)
INSERTAdminActionLogaction=create, entity_type=Variant

Update stock for a variant

UPDATEVariantstock_qty
INSERTAdminActionLogaction=update, entity_type=Variant, detail=stock change

Upload a product/variant image

INSERTProductImagenew row (product_id, variant_id?, url, sort_order, is_primary)
INSERTAdminActionLogaction=upload, entity_type=ProductImage

Create/verify a user (support action)

INSERTUsernew row (mobile_number, full_name, is_verified)
INSERTAdminActionLogaction=create, entity_type=User

Process order status change

UPDATEOrderstatus
INSERTOrderStatusHistorynew row (order_id, status, changed_by=admin)
INSERT/UPDATEShipmentstatus / tracking_code / shipped_at / delivered_at
INSERTAdminActionLogaction=update, entity_type=Order

Record a payment result (webhook/manual)

UPDATEPaymentTransactionstatus, ref_code, paid_at
UPDATEOrderstatus → paid (if transaction succeeded)
INSERTOrderStatusHistorynew row (order_id, status=paid, changed_by=system)

Approve/reject a return request

UPDATEReturnRequeststatus → exchanged / refunded / rejected
UPDATEVariantstock_qty (restock original, decrement exchange target)
INSERTOrderStatusHistorynew row (order_id, status=returned) — if refunded/exchanged
INSERTAdminActionLogaction=update, entity_type=ReturnRequest

Moderate a comment/review

UPDATECommentvisibility/approval flag (not modeled yet — open question)
INSERTAdminActionLogaction=moderate, entity_type=Comment

Each customer action below lists the tables it touches, in order.

Register / log in via OTP

INSERT (if new)Usernew row (mobile_number, is_verified=false)
INSERTOTPCodenew row (user_id, code, purpose=login/register, expires_at)
UPDATEOTPCodeused=true (on verification)
UPDATEUseris_verified=true (on first successful OTP)

Browse / search / filter catalog

SELECTProduct, Category, Variant, ProductImageread-only — no writes

Add item to cart

INSERT/UPDATECartItemnew row, or quantity += 1 if (user_id, variant_id) already exists

Add / edit a shipping address

INSERT/UPDATEAddressnew row, or update existing (recipient_name, province, city, full_address)

Place an order (checkout)

INSERTOrdernew row (user_id, address_id, status=placed, total_amount, payment_method)
INSERTOrderItemone row per cart line (order_id, variant_id, quantity, unit_price)
UPDATEVariantstock_qty -= quantity for each item
DELETECartItemrows for the checked-out items
INSERTOrderStatusHistorynew row (order_id, status=placed, changed_by=customer)

Pay online (gateway redirect)

INSERTPaymentTransactionnew row (order_id, gateway, amount, status=initiated)
UPDATEPaymentTransactionstatus → success/failed, ref_code, paid_at (on gateway callback)
UPDATEOrderstatus → paid (if success)
INSERTOrderStatusHistorynew row (order_id, status=paid, changed_by=system)

Track order status

SELECTOrder, OrderStatusHistory, Shipmentread-only — no writes

Leave a review / comment

INSERTCommentnew row (product_id, user_id, order_id?, rating, fit_feedback, body)

Request a return / exchange

INSERTReturnRequestnew row (order_item_id, reason, requested_exchange_variant_id?, status=pending)
